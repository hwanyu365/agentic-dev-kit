# agentic-dev-kit — 결정 페이지 (`/adk:decide`)

## 1. 개요

- 문서 정보: 작성 2026-11-22 / 기준 커밋 `826a421` (origin/main) / 이슈 GH#91
- 기능: 저장소 소유자에게 받을 결정을 기능별 "기존 | 변경안" 그림과 바로 아래 선택지로 보여 주고, 고른 값을 한 번에 넘겨받는 페이지를 만든다
- 목적 (Why)
  - 결정은 지금 대화의 글·표로 받는다 (`/adk:spec` 2 는 한 번에 하나씩 묻는다).
  - 결정이 여럿이고 화면이 바뀌는 제안이면 문제 목록·시안·결정 표가 떨어져 있어 "무엇이 무엇인지, 무엇이 추가되는지" 알 수 없다 → 결정하지 못한다.

## 2. 목표 및 범위

- In Scope: 스킬 `plugins/adk/skills/decide/` (`SKILL.md`, `templates/decision-page.html`), `/adk:spec` 2 의 연결, 템플릿·adk `CLAUDE.md` 절차 도구 줄, README 명령 표·흐름도, `docs/benchmark.md`, adk `CLAUDE.md` 기술 스택·검증 명령과 `verify.sh` (CI `sh` job 은 `tests/*.test.sh` 를 모두 돌린다)
- Out of Scope
  - 문제 찾기·시안·심사 단계 → 결정 페이지만 다룬다 (D1)
  - 세션이 페이지의 고른 값을 직접 읽는 것 → 고른 값은 소유자 브라우저에만 있다 (FR#6)
  - Artifact 감시·코멘트로 피드백 받기 → 피드백은 세션 대화로 받는다 (D4)

## 3. 요구사항

### 3.1 사용자 스토리

- `US#1` 저장소 소유자로서, agent 가 제안한 여러 결정을 무엇이 어떻게 바뀌는지 보면서 그 자리에서 고르기 위해, 기능별 "기존 | 변경안" 그림 아래에 선택지를 두고 고른 값을 한 번에 넘기는 결정 페이지를 원한다 [요구사항] → FR#1~FR#10

### 3.2 기능 요구사항

- `FR#1` [요구사항] 기능마다 한 블록이 아래 순서로 보인다.

  ```
  Given 소유자에게 받을 결정이 둘 이상이고 화면·동작이 바뀌는 제안이 있다
  When  /adk:decide 로 결정 페이지를 만든다
  Then  블록마다 [번호·제목·문제 한 줄 → 기존|변경안 그림(같은 크기로 나란히) → 바뀌는 점(추가·변경·삭제) → 결정] 순서다
  And   좁은 화면에서는 기존·변경안이 위아래로 놓인다
  ```

- `FR#2` [요구사항] 결정은 선택지 라디오다.

  ```
  Given 결정이 있는 블록
  Then  권장안이 기본으로 골라져 있고 "권장" 표시와 "권장 이유:" 로 시작하는 한 줄이 있다 → 고른 값과 무관하게 권장안의 이유로 읽힌다
  Given 결정이 없는 블록
  Then  "결정할 것 없음" 으로 표시하고 결정 모음에 넣지 않는다
  And   맨 위 목차에서 결정이 있는 블록이 구분된다
  ```

- `FR#3` [요구사항] 맨 아래 결정 모음

  ```
  Given 소유자가 선택지를 고른다
  Then  결정 모음에 블록 순서대로 "{ID} {이름}: {고른 값} (권장|권장 아님)" 한 줄씩 자동으로 모인다
  And   전부 권장안이면 첫 줄이 "권장대로" 다
  ```

- `FR#4` [요구사항] 복사

  ```
  When  [결정 복사] 를 누른다
  Then  결정 모음이 클립보드에 복사되고 "복사했습니다." 를 표시한다
  When  클립보드 쓰기가 막힌다
  Then  결정 모음 글을 선택해 두고 직접 복사하라고 표시한다
  ```

- `FR#5` [요구사항] 고른 값 유지 (agent 기본값, 소유자 확인 2026-11-22)

  ```
  Given 소유자가 고른 뒤 같은 URL 로 다시 발행됐다
  Then  페이지 경로·블록 ID 별로 브라우저에 저장된 값을 다시 고른다
  When  저장값이 없거나, 지금 선택지에 없는 값이거나, 브라우저 저장소 접근이 막힌다
  Then  권장안을 고른다
  ```

- `FR#6` [요구사항] 넘겨받기 (실패 경로)

  ```
  Given 결정 페이지를 발행했다
  When  세션이 소유자가 고른 값을 알아야 한다
  Then  세션은 페이지에서 읽으려 하지 않고 [결정 복사] 결과를 붙여 넣어 달라고 안내한다
  ```

- `FR#7` [요구사항] 발행 (agent 기본값, 소유자 확인 2026-11-22)

  ```
  Given 세션에 Artifact 도구가 있다
  Then  비공개 Artifact 로 발행하고 링크를 안내한다
  Given Artifact 도구가 없거나 발행이 거부된다
  Then  로컬 HTML 파일로 만들고 절대 경로를 안내한다. 이후 절차는 같다
  ```

- `FR#8` [요구사항] 피드백 반영

  ```
  Given 소유자가 한 블록에 지적을 남긴다
  Then  세션은 그 블록을 고쳐 같은 파일 경로로 다시 발행하고(같은 URL) 바꾼 것을 짧게 보고한다
  ```

- `FR#9` [요구사항] 기록

  ```
  Given 소유자가 결정 모음을 붙여 넣는다
  Then  세션은 결정 요약과 페이지 링크(또는 경로)를 main 클론 .adk/handoff.md 의 결정 절에 남긴다
  And   결정을 작업 단위로 나눈 안을 보여 확인받고, 확인된 단위만 /adk:spec 0 의 규칙으로 이슈를 만든다
  ```

- `FR#10` [요구사항] `/adk:spec` 2 연결 (소유자 결정 2026-11-22)

  ```
  Given /adk:spec 2 에서 받을 결정이 둘 이상이고 화면·동작이 바뀌는 제안이 있다
  Then  한 번에 하나씩 묻는 대신 /adk:decide 로 묻는다
  And   넘겨받은 결정은 이슈로 나누지 않고 그 스펙에 적어 /adk:spec 을 이어 간다
  ```

### 3.3 비기능 요구사항

- `NFR#1` [요구사항] 그림 원칙
  - 기존 그림은 실제 화면 캡처와 실제 문구를 기준으로 그린다.
  - 변경안은 기존과 같은 부품·색으로 차이만 보이게 그린다.
  - 장식 아이콘·여러 겹 강조를 더하지 않는다.
  - 판단에 쓰는 정보는 남긴다.
  - 이미 다른 표시에 포함된 정보를 따로 나열하지 않는다.
  - 좁은 자리(버튼) 문구는 짧게 둔다 → 번역하면 잘린다.
  - 그림 설명은 실제 동작과 맞춘다.
- `NFR#2` [요구사항] 페이지는 파일 하나로 동작한다.
  - 외부 스크립트·스타일을 읽지 않는다 → 로컬 파일로 열어도 같게 동작한다.
  - 다크 모드와 휴대폰 폭(가로 스크롤 없음)을 지원한다.
- `NFR#3` [요구사항] 결정 모음·저장값 복원 로직은 DOM 없이 호출할 수 있는 함수로 둔다 → npm 패키지 없이 Node 내장 모듈로 단언한다 (D2).
  - 페이지를 만들 때 틀의 스크립트·스타일은 고치지 않고 블록 마크업만 바꾼다 → 테스트한 로직이 그대로 발행된다.
