# agentic-dev-kit — 작업 습관 규칙

## 1. 개요

- 문서 정보: 작성 2026-11-20 / 기준 커밋 `df5a528` (origin/main) / 이슈 GH#76
- 기능: 저장소 소유자가 반복해서 지적한 작업 습관을 틀의 원칙·절차 문서에 규칙으로 둔다
- 목적 (Why)
  - 같은 지적이 프로젝트마다 반복된다 → 적용 저장소가 `/adk:init --update` 로 받는 문서에 있어야 한다.
  - 규칙마다 실패 경로가 있다: 진행을 못 읽는 백그라운드 작업, 오류로 빈 출력을 "없음" 으로 읽음, 리팩터 잔재, 확인 안 된 불일치·이미 고쳐진 결함의 등록, 낡는 제목.

## 2. 목표 및 범위

- In Scope: 템플릿·adk `CLAUDE.md` 원칙·GIT 절, 템플릿·adk PR 템플릿, `/adk:tdd` Refactor, `/adk:ship` followup 3-1, `/adk:verify` 2·4, `/adk:spec` 0, `/adk:deps` 2
- Out of Scope
  - 리뷰 기준(`review.md`·`claude-review.yml`)에 Refactor 규칙을 넣는 것 → 저장소 소유자 결정(2026-11-20): `/adk:tdd` 에만 둔다
  - 규칙 위반을 기계로 찾는 검사 → 대상이 명령 사용 습관과 문장 판단이라 문자열 검사로 판정할 수 없다

## 3. 요구사항

- `US#1` [요구사항] 저장소 소유자로서, 프로젝트마다 같은 지적을 다시 하지 않도록, 반복해서 지적한 작업 습관이 ADK 원칙·절차에 들어가 있기를 원한다. → FR#1~FR#6
- `FR#1` [요구사항] 원칙: 백그라운드 작업은 진행 신호를 읽을 수 있게 시작한다.
  - 출력은 파일로 받고 필터는 읽을 때 건다 → 백그라운드 명령 끝에 `| tail`·`| head` 를 붙이면 버퍼링돼 끝날 때까지 아무것도 나오지 않는다.
  - 프로세스가 살아 있는 것은 진행 근거가 아니다 → 주기적으로 신호를 기대치와 대조한다.
- `FR#2` [요구사항] 원칙: 빈 출력은 "없음" 의 근거가 아니다 ("명령 출력 없이 완료를 선언하지 않는다" 옆).
  - 확인 명령의 stderr 를 버리지 않는다 → 명령이 오류로 끝나 출력이 비면 "없음" 으로 읽힌다.
  - 인자가 `-` 로 시작할 수 있으면 `--` 로 옵션을 끝낸다 → 파일 이름이 옵션으로 읽혀 오류가 난다.
- `FR#3` [요구사항] `/adk:tdd` Refactor
  - 타입·함수를 옮기면 re-export 로 기존 import 를 살리지 않고 호출부 import 를 고친다 → 옛 경로가 남아 두 경로가 함께 쓰인다.
  - 리팩터 뒤 테스트에서만 쓰이게 된 제품 코드는 지우고, 테스트는 공개된 동작으로 같은 사실을 단언하게 고친다 → 테스트를 위한 제품 코드가 남지 않게 한다.
- `FR#4` [요구사항] subagent·대조 스크립트가 낸 "불일치" 는 직접 다시 확인한 뒤 사실로 다룬다 (`/adk:ship` followup 3-1 의 등록, `/adk:verify` 2 의 subagent 표 재확인).
  - 생산측이 내보내는 것을 수신측이 실제로 읽는지(불러올 때 보정하는 경로 포함) 추적한다.
  - 비교한 두 데이터가 같은 대상인지 확인한다.
- `FR#5` [요구사항] 결함으로 등록·보고하기 전에 최신 base 로 시험한다 (`/adk:ship` followup 3-1, `/adk:verify` 4).
  - 시험 직전 `git fetch` 하고 `origin/main` 을 별도 워크트리(detached)로 꺼내 재현한다 → 뒤처진 브랜치에서는 이미 고쳐진 것을 결함으로 등록한다.
  - PR 브랜치는 rebase 하지 않는다 → 열린 PR 의 head 가 바뀌면 재리뷰가 필요하고 `pr` 저장소에서는 승인이 풀린다 (저장소 소유자 결정 2026-11-20)
  - 관련 저장소의 open·merged PR 과 이슈를 조회한다.
- `FR#6` [요구사항] PR·이슈 제목에 갱신 때 바뀌는 값을 쓰지 않는다 (템플릿·adk `CLAUDE.md` GIT 절, PR 템플릿, 이슈를 만드는 `/adk:spec` 0·`/adk:deps` 2).
  - 건수·비율·커버리지 같은 수치와 본문을 열면 보이는 정보는 제목에서 뺀다 → 갱신 때마다 제목이 낡는다.
- `NFR#1` [요구사항] 기존 원칙과 겹치는 규칙은 새 절을 만들지 않고 해당 줄 옆에 둔다.
