# /adk:decide

결정이 하나이거나 화면·동작이 바뀌지 않으면 쓰지 않는다 → 대화로 묻는다 (`/adk:spec` 2).

## 1. 만들기

- 틀: 이 스킬 폴더의 `templates/decision-page.html` 을 복사해 예시 블록을 바꾼다. 스크립트·스타일은 고치지 않는다 → 테스트한 로직이 그대로 발행된다.
- 블록 하나 = 기능 하나. `section.item` 의 `id` 가 결정 ID(`D1`…)이고 `data-name` 이 이름이다 → 결정 모음 줄 `{ID} {이름}: {값} (권장|권장 아님)` 이 이 두 값으로 만들어진다.
  - 순서: `h2`(번호·제목) → `.problem`(문제 한 줄) → `.compare`(`.before`·`.after` 같은 크기로 나란히) → `.changes`(추가 `.add`·변경 `.mod`·삭제 `.del`) → `.decision`
  - 결정: 라디오 `name` 은 블록 ID, `value` 는 결정 모음에 들어갈 선택지 이름이다. 권장안 하나에만 `data-recommended checked` 와 "권장" 표시를 두고 `.reason` 에 "권장 이유:" 로 시작하는 한 줄을 쓴다 → 다른 값을 골라도 권장안의 이유로 읽힌다.
  - 결정이 없는 블록(다른 결정에 따라 함께 바뀌는 것)은 `.decision` 대신 `.no-decision` 에 "결정할 것 없음" 을 쓴다.
  - 목차: 블록마다 한 줄. 결정이 있는 블록의 링크에만 `has-decision` 을 붙인다.
- 외부 스크립트·스타일·이미지 URL 을 넣지 않는다 → 로컬 파일로 열어도 같게 동작한다.
- 선택지를 바꿀 때 블록 ID 는 유지한다 → 소유자가 이미 고른 값이 그 ID 로 브라우저에 남아 있다. 지금 선택지에 없는 값이면 권장안으로 돌아간다.

## 2. 그림 원칙

- 기존: 실제 화면 캡처와 실제 문구를 기준으로 그린다.
- 변경안: 기존과 같은 부품·색으로 차이만 보이게 그린다.
  - 장식 아이콘·여러 겹 강조를 더하지 않는다.
  - 판단에 쓰는 정보(예: 사라질 항목 목록)는 지우지 않는다.
  - 이미 다른 표시에 포함된 정보를 따로 나열하지 않는다.
  - 좁은 자리(버튼) 문구는 짧게 둔다 → 번역하면 잘린다.
- 그림 설명(`.changes`·`.reason`)은 실제 동작과 맞춘다. 그림에 없는 동작을 설명에 쓰지 않는다.

## 3. 발행

- Artifact 도구가 있으면 비공개 Artifact 로 발행하고 링크를 알린다. 발행 뒤 감시는 걸지 않는다 → 피드백은 대화로 받는다.
- 도구가 없거나 발행이 거부되면 로컬 HTML 파일로 두고 절대 경로를 알린다. 이후 절차는 같다.
  - Artifact 는 claude.ai 로그인 세션에서만 쓸 수 있다 → API 키·클라우드 제공자 세션, `-p` 실행, 조직이 끈 경우에는 없다.
- 알릴 때 함께 적는다: 고른 뒤 맨 아래 [결정 복사] 결과를 붙여 넣어 달라.

## 4. 피드백

- 소유자가 블록에 지적을 남기면 그 블록을 고치고 **같은 파일 경로로** 다시 발행한다 → URL 이 유지된다. 경로를 바꾸면 새 URL 이 생겨 소유자가 옛 페이지를 본다.
- 바꾼 블록과 내용을 한두 줄로 보고한다.

## 5. 넘겨받기와 기록

- 고른 값은 소유자 브라우저에만 있다 → 세션은 페이지에서 읽으려 하지 않는다. 붙여 넣은 결정 모음만 결정으로 본다.
- 결정 요약과 페이지 링크(또는 경로)를 main 클론 `.adk/handoff.md` 의 "결정" 절에 남긴다 (`/adk:handoff` 양식).
- 결정을 작업 단위로 나눈 안을 보여 주고 확인받는다. 확인된 단위만 `/adk:spec` 0 의 규칙으로 이슈를 만든다.
  - `/adk:spec` 2 에서 부른 경우에는 이슈로 나누지 않고 결정을 그 스펙에 적어 `/adk:spec` 을 이어 간다.
